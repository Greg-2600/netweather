# RIPE Atlas profile

`netweather` ships an **optional** compose profile that runs RIPE's official
software probe. It is off by default and is a **separate trust domain** from
the monitor.

```
docker compose --profile ripe-atlas up -d
```

## What it is

The profile runs `ghcr.io/ripe-atlas/ripe-atlas-probe`, RIPE's daemon. It
performs measurements for RIPE's network under RIPE's terms and the operator's
Atlas account. `netweather` never talks to its socket, never reads its data and
never wraps it; turning the profile on or off changes no probe, feed or page
(`DESIGN.md` §8.6).

## What RIPE sees

Running the probe is a second relationship with a third party, and it is worth
stating plainly rather than leaving it in a compose comment:

- **The operator's public IP address**, because that is the measurement
  source.
- **Host uptime and availability** of this machine, as seen by RIPE's
  infrastructure.
- **Traffic generated by RIPE's measurements**, which is RIPE's, not
  netweather's: it is not counted against `NETWEATHER_DAILY_MB`, and it is not
  governed by this project's rate limits or target list.
- The probe may need **host networking and raw sockets** to measure from the
  host's real address, which is why the profile declares them explicitly.

Nothing about the monitor's target list, credentials, logs or database is sent
to RIPE by this profile. The reverse is also true: netweather does not ingest
Atlas results. The `atlas` feed plugin is specified and deliberately not
shipped (`ACCEPTABLE_USE.md` §9): an Atlas measurement carries no target id for
this monitor to map onto, and guessing one would turn evidence into a verdict.

## Scope

- Off by default; never part of the base stack.
- The profile's traffic and terms are RIPE's; the operator accepts them by
  enabling it.
- Removing the profile (`docker compose --profile ripe-atlas down`) stops the
  probe and changes nothing in netweather.
